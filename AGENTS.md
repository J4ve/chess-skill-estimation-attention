# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- **Environment**: the repo's own `.venv` may be unusable on some machines (e.g. unreadable interpreter symlinks on an NTFS-backed checkout). Use a venv outside the repo (`python3.12 -m venv ~/venvs/ratingnet-web`), CPU torch via `pip install torch --index-url https://download.pytorch.org/whl/cpu`, then `pip install -r requirements.txt`. Point `RATINGNET_CHECKPOINT` at the frozen checkpoint rather than copying it; see README "Frozen weights".
- **Tests need no model.** `tests/` covers baseline resolution (`src/baseline.py`), critical-move ranking (`src/critical_moves.py`), Lichess ID/URL parsing and HTTP error mapping (`src/lichess_client.py`, mocked with `httpx.MockTransport`), and PGN parsing errors (`api._pgn_to_tensor_inputs`, which raises before any tensor/model code runs). None of these load the checkpoint, so `pytest tests/` runs fast with no `RATINGNET_CHECKPOINT` set.
- **chessboard.js sizes itself once, at construction, from its container's current rendered width.** If the container is inside a `hidden` element at that point, the board renders at zero size and never recovers on its own. Fix: call `board.resize()` right after un-hiding the container (see `src/static/app.js`, `renderResult()`).
- **`GET /` serves `index.html` directly (not through the `/static` mount)**, so every asset reference inside it (`<link>`, `<script src>`, the `pieceTheme` URL passed to chessboard.js) must be an absolute `/static/...` path, not a path relative to the page. Relative paths there resolve against `/`, not `/static/`, and 404 silently in the browser console. `app.js`'s own `import` statements are the one exception: those resolve relative to `/static/app.js`'s own URL, so `./vendor/...` is correct there.
- **Browser automation in this sandbox**: `chrome-devtools-axi` (and the `claude-in-chrome` MCP extension) may have no reachable Chrome/Chromium binary and fail with a generic "No page is currently selected" error regardless of retries. Workaround: `npx --yes @puppeteer/browsers install chrome@stable --path ~/.cache/puppeteer` to fetch a real Chrome for Testing binary, then drive it directly with Playwright (`chromium.launch(executable_path=..., headless=True)`) instead of the MCP browser tools. Do not run the installer without `--path`; it silently installs into the current working directory.
- **Lichess game export**: `GET https://lichess.org/game/export/{id}?clocks=true&evals=false` with `Accept: application/x-chess-pgn` and a descriptive `User-Agent`. 404 = not found, 429 = rate limited. An ongoing game has PGN header `Result "*"` and is delayed a few moves by Lichess itself.
- **A responsive Chart.js canvas needs an explicit-height parent, or it grows without bound.** With `responsive: true, maintainAspectRatio: false` and no fixed height on the canvas's immediate container, each `chart.update()` recomputes the canvas size from the container's rendered size, which itself grew from the previous update; the canvas balloons across navigation clicks until the page is thousands of pixels tall. Fix: wrap the canvas in a container with a fixed CSS `height` (see `.chart-canvas-wrap` in `src/static/styles.css`), never rely on content-based auto height for a responsive chart.
- **Lichess live streaming**: `GET /api/stream/game/{id}` sends one metadata line (no `fen` key), then replays *every* ply from the start of the game as its own `{fen, lm?, wc, bc}` line (even for a game already in progress when you connect) before continuing live, then a final `{fen, status, winner, ...}` line when the game ends. `GET /api/tv/feed` is different: it sends only the *current* snapshot on connect (a `{"t":"featured","d":{id, players, fen}}` event, no backlog) plus live `{"t":"fen","d":{fen, lm, wc, bc}}` diffs, with a fresh `featured` event whenever TV switches games. Both give clocks as integer seconds (`wc`/`bc`), not the `H:MM:SS` PGN format. See `src/live.py` for the full parsing/bookkeeping and `tests/test_live.py` for mocked-stream coverage.
- **Lichess TV occasionally features a non-standard game** (e.g. a variant) even on channels that are normally standard chess; pushing its moves onto a fresh `chess.Board()` raises deep inside python-chess (`AssertionError` in `Board.san()`/`Board.push()`), not a catchable "invalid input" error. Any code that walks a live move feed onto a `chess.Board()` must catch broadly around each `add_move`-equivalent call and skip/abort that one game, not just wrap the initial PGN parse (see `src/live.py`'s `stream_game`/`stream_tv`).
- **A background server started from inside a single Bash tool call dies when that tool call returns**, even with `nohup ... &`; the sandbox appears to kill the process group at the end of the invocation. Start any long-lived local server (e.g. `python src/api.py` for manual/browser testing) via the Bash tool's `run_in_background: true` option instead, which keeps it alive across subsequent tool calls.
- **A class rule that sets `display` unconditionally defeats the `hidden` DOM attribute**, since any author-stylesheet declaration beats the browser's own low-priority `[hidden] { display: none }` rule regardless of source order; toggling `el.hidden = true` on such an element does nothing visible. This bit `.live-status-panel` (`display: flex` in its base rule) in `src/static/styles.css`, fixed with an explicit `.live-status-panel[hidden] { display: none; }` override. Any new element whose class sets `display` and that JS also toggles via `.hidden` needs the same `[hidden]` override alongside it.
